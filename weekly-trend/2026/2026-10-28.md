## 1. 개요

이번 주에는 AI 에이전트를 실제 업무에 연결하는 기반 도구가 두드러진다. [Orca](https://github.com/stablyai/orca)는 여러 에이전트의 작업을 독립된 Git 작업 트리에서 관리하고, [Graphify](https://github.com/Graphify-Labs/graphify)는 코드와 문서의 관계를 질의 가능한 지식 그래프로 만든다. 실행을 관리하는 환경과 프로젝트 맥락을 제공하는 도구가 함께 발전하는 흐름으로 읽힌다.  
에이전트가 수행할 업무를 구체적인 절차로 제공하는 스킬도 눈에 띈다. [security-audit-skill](https://github.com/cloudflare/security-audit-skill)은 취약점 탐색과 독립 검증을 분리하고, [Android skills](https://github.com/android/skills)는 Android 개발 지침을 모듈화한다. 이들의 공통점은 범용 모델에 전문 업무의 판단 기준과 절차를 보완한다는 점이다.

## 3. 주요 리포지토리 분석

> **[cloudflare/security-audit-skill](https://github.com/cloudflare/security-audit-skill)**  
> **해결하는 문제와 접근:** 에이전트가 취약점 후보를 제시하는 것만으로는 실제 보안 결함인지 판단하기 어렵다. 이 스킬은 아키텍처와 신뢰 경계를 파악하고 검사 범위를 기록한 뒤, 후보를 발견한 에이전트와 별개의 검증자가 반증을 시도하도록 절차를 구성한다. 최종 기록의 소스 근거도 독립적으로 확인해 탐색과 판정 사이에 검증 단계를 둔다.  
> **핵심 기능과 활용 가치:** 발견 사항을 확인됨, 추가 검증 필요, 기각으로 구분하고 구조화된 기록과 보고서를 만든다. 추가 검증이 필요한 항목에는 해결되지 않은 사실을 명시하며 심각도를 부여하지 않는다. 이전 감사의 검사 범위와 결과를 이어받아 누락 영역과 변경된 코드를 다시 살피므로, 반복 감사에서 검토 근거를 관리하는 데 유용하다.  
> **활용 제약과 트렌드 연결:** 도구 호출과 병렬 하위 에이전트를 지원하는 코딩 에이전트가 필요하다. 대상 코드 실행에는 네트워크 차단, 환경 변수 제한, 자원·쓰기 경로 제한을 강제하는 운영체제 수준의 샌드박스가 요구되며, 조건이 갖춰지지 않으면 실행 검증을 보류한다. Android skills가 전문 개발 지침을 제공하듯 업무 절차를 스킬로 전달하되, 이 프로젝트는 보안 판정의 근거와 독립 검증에 초점을 맞춘다. [프로젝트 설명](https://github.com/cloudflare/security-audit-skill/blob/HEAD/README.md)
>  
> **[stablyai/orca](https://github.com/stablyai/orca)**  
> **해결하는 문제와 접근:** 여러 코딩 에이전트를 동시에 사용하면 작업 디렉터리, 실행 상태, 변경 사항 검토를 함께 관리해야 한다. Orca는 에이전트별 Git 작업 트리를 분리하고 하나의 화면에서 추적한다. 같은 요청을 여러 에이전트에 맡긴 뒤 결과를 비교하고 채택한 변경을 병합하는 흐름을 지원한다.  
> **핵심 기능과 활용 가치:** 변경 내역의 특정 줄에 의견을 남겨 에이전트에 돌려보내고, GitHub·Linear의 작업에서 작업 트리를 열 수 있다. 브라우저에서 선택한 UI 요소의 HTML·CSS·화면 이미지를 프롬프트에 전달하는 기능은 화면 수정에 필요한 맥락을 제공한다. SSH 원격 작업과 모바일 완료 알림·후속 지시 기능은 개발용 컴퓨터를 계속 지켜보지 않아도 작업을 이어가도록 돕는다.  
> **활용 제약과 트렌드 연결:** 기존 CLI 에이전트와 사용자의 구독을 연결하는 환경이므로 모델 사용 조건은 각 에이전트 공급자에 의존한다. 모바일 기능은 데스크톱 앱과 연결해 작업을 감시하고 지시하는 방식이다. T3 Code와 마찬가지로 여러 에이전트에 접근하는 접점을 통합하며, Orca의 작업 트리 분리와 변경 검토 기능은 병렬 개발 결과를 사람이 비교하고 통합하는 데 가치를 둔다. [프로젝트 설명](https://github.com/stablyai/orca/blob/HEAD/README.md)
>  
> **[Graphify-Labs/graphify](https://github.com/Graphify-Labs/graphify)**  
> **해결하는 문제와 접근:** 여러 파일에 흩어진 함수·모듈·문서의 관계는 개별 파일 검색만으로 파악하기 어렵다. Graphify는 코드를 로컬에서 구문 트리로 분석하고 호출·가져오기·상속 관계 등을 지식 그래프로 연결한다. 벡터 저장소 대신 관계 경로를 탐색하며, 소스에서 직접 추출한 연결과 도구가 추론한 연결을 구분해 근거를 판단할 수 있게 한다.  
> **핵심 기능과 활용 가치:** 개념 사이의 경로 탐색, 특정 개념의 연결 설명, 질문에 관련된 부분 그래프 조회를 제공한다. 문서와 PDF 등도 같은 그래프에 연결할 수 있으며, 시각화와 구조 보고서로 모듈 간 연결과 하위 시스템을 살펴볼 수 있다. 이는 낯선 코드베이스의 구조를 익히거나 변경과 관련된 의존 관계를 좁혀 살펴보는 데 유용하다.  
> **활용 제약과 트렌드 연결:** 코드만 분석할 때는 LLM 없이 로컬 처리가 가능하지만, 문서·PDF·이미지의 의미 추출에는 모델이 필요하며 선택한 백엔드에 따라 외부 전송이 발생할 수 있다. 그래프의 추론 연결을 직접 확인된 사실과 구별해 읽어야 한다. ai-memory가 에이전트 사이의 장기 기억과 작업 인계를 다룬다면, Graphify는 코드와 자료의 관계를 재사용 가능한 맥락으로 만든다는 점에서 에이전트의 지속적인 프로젝트 이해를 보완한다.
