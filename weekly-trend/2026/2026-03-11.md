# GitHub 주간 트렌드 리포트 (2026-03-11)

## 1. 개요
이번 주 GitHub 주간 트렌드는 _AI 에이전트의 상품화_가 가장 강하게 드러났습니다. 상위 14개 저장소 가운데 다수가 에이전트 프레임워크, 에이전트 스킬 모음, 샌드박스, 추론용 강화학습, 답변 엔진처럼 _모델 그 자체보다 모델을 일하게 만드는 계층_에 집중되어 있습니다. 이제 관심의 중심은 "어떤 모델을 쓰는가"보다 "어떤 구조로 자동화하고 배포하는가"로 옮겨가고 있습니다.

동시에 _개성 있는 인터페이스를 가진 AI 동반자_와 _현실 신호를 읽는 엣지 AI_도 강세였습니다. AIRI처럼 음성 대화와 게임 상호작용을 묶은 디지털 캐릭터, RuView처럼 WiFi 신호만으로 자세와 생체 상태를 추정하는 프로젝트가 높은 주간 증가폭을 기록했습니다. AI가 채팅창을 넘어 캐릭터, 공간, 센서 레이어로 확장되는 흐름이 확인됩니다.

인프라 측면에서는 _실행 환경의 표준화_가 눈에 띕니다. OpenSandbox, Qwen-Agent, DeerFlow 같은 프로젝트는 샌드박스, 메모리, 도구 호출, 브라우저 확장, 코드 실행 같은 요소를 재사용 가능한 플랫폼으로 묶고 있습니다. 이는 앞으로의 경쟁력이 단순한 데모보다 _복잡한 작업을 안정적으로 운영하는 엔지니어링 역량_에 달려 있음을 보여줍니다.

## 3. 주요 리포지토리 분석

_[msitarzewski/agency-agents](https://github.com/msitarzewski/agency-agents)_
이 저장소는 에이전트를 "프롬프트 예제"가 아니라 _역할, 성격, 작업 절차, 산출물_까지 갖춘 패키지로 다룹니다. 프런트엔드, 커뮤니티 운영, 현실 검증처럼 세분화된 전문가 에이전트를 모아 둔 방식은 앞으로의 경쟁 포인트가 모델 성능 자체보다 _업무 단위의 재사용성_에 있다는 점을 보여줍니다. 이번 주 압도적인 증가폭은 에이전트 활용이 실험을 넘어 팀 운영 도구로 소비되고 있음을 시사합니다.

_[moeru-ai/airi](https://github.com/moeru-ai/airi)_
AIRI는 단순 채팅봇이 아니라 음성, 캐릭터성, 게임 연동을 묶은 _디지털 동반자_에 가깝습니다. 최신 브라우저 기술을 중심으로 설계되어 웹, 데스크톱, 모바일까지 확장 가능하고, Minecraft나 Factorio 같은 외부 세계와 상호작용하는 방향이 분명합니다. 이는 생성형 AI가 텍스트 인터페이스에서 벗어나 _지속적으로 관계를 형성하는 캐릭터형 제품_으로 이동하고 있음을 보여주는 사례입니다.

_[ruvnet/RuView](https://github.com/ruvnet/RuView)_
RuView는 카메라 없이도 공간을 인식하는 방향을 전면에 내세웁니다. WiFi와 각종 무선 신호의 변화를 읽어 자세, 호흡, 심박, 존재 여부를 실시간으로 복원하고, 값싼 ESP32 센서 메시에서도 동작하도록 설계돼 있습니다. 이번 상승은 AI 트렌드가 소프트웨어 자동화에 머무르지 않고 _센서 융합과 프라이버시 친화적 공간 인식_으로 빠르게 넓어지고 있음을 보여줍니다.

_[bytedance/deer-flow](https://github.com/bytedance/deer-flow)_
DeerFlow는 단일 에이전트보다 _서브에이전트 오케스트레이션_에 초점을 둡니다. 메모리, 샌드박스, 스킬, 검색 도구를 연결해 분 단위가 아니라 수십 분에서 수시간짜리 작업을 처리하는 구조가 핵심입니다. 2.0으로 전면 재작성되면서도 빠르게 주목받은 것은, 시장의 관심이 데모성 자동화보다 _복합 작업을 안정적으로 분해하고 실행하는 프레임워크_로 이동하고 있기 때문입니다.

_[alibaba/OpenSandbox](https://github.com/alibaba/OpenSandbox)_
OpenSandbox는 에이전트 시대의 공용 실행 기반을 노리는 프로젝트입니다. 다국어 SDK, 통합 샌드박스 API, Docker와 Kubernetes 런타임, 코드 인터프리터와 브라우저 자동화 예시까지 묶어 두어 다양한 에이전트 시스템이 같은 실행 모델 위에 올라갈 수 있게 합니다. 이는 앞으로 에이전트 경쟁이 프롬프트만이 아니라 _격리, 보안, 확장성, 운영 표준화_에서 결정될 가능성이 크다는 점을 잘 보여줍니다.
