# GitHub 주간 트렌드 리포트 (2026-11-11)

## 1. 개요

에이전트를 실제 업무에 연결하는 도구와 그 결과를 신뢰할 수 있게 만드는 장치가 함께 확장되고 있다. T3 Code는 여러 코딩 에이전트를 모바일·웹·데스크톱에서 제어하고, agent-desktop과 agent-browser는 각각 컴퓨터와 브라우저를 조작할 수단을 제공한다. 이는 에이전트 활용의 관심이 답변 생성에서 작업 환경과의 연결로 넓어지고 있음을 보여준다.  
Security Audit Skill은 발견한 취약점 후보를 별도 에이전트가 검증하도록 하고, Auto Ontology는 데이터의 업무 용어와 관계를 정리해 질의의 근거로 제공한다. 두 프로젝트는 서로 다른 영역에서 검증 가능한 근거를 다루며, 실행 범위를 넓히는 것과 함께 결과의 타당성을 확인하는 구조가 필요하다는 흐름을 보여준다.

## 3. 주요 리포지토리 분석

> **[pingdotgg/t3code](https://github.com/pingdotgg/t3code)**  
> T3 Code는 컴퓨터에서 동작하는 코딩 에이전트를 여러 기기에서 다루는 문제에 초점을 맞춘다. Claude Code, Codex, Cursor 등 여러 에이전트를 제어하며 iOS·Android 앱, 웹 앱, Electron 데스크톱 앱을 제공한다. 에이전트마다 다른 사용 환경을 오가는 개발자에게 공통 제어 창구를 제공하고, 컴퓨터 앞을 벗어난 상황에서도 작업에 접근할 수 있게 한다.  
> agent-browser와 agent-desktop이 에이전트가 조작할 대상을 확장한다면, T3 Code는 사람이 에이전트에 접근하는 접점을 확장한다. 기존 에이전트와 구독을 활용하는 구조이므로 지원 제공자의 사용 준비와 인증이 필요하다. 프로젝트는 초기 단계이며 버그가 있을 수 있다고 명시하므로, 일상적인 개발 환경에 적용할 때 안정성을 확인할 필요가 있다.
>  
> **[cloudflare/security-audit-skill](https://github.com/cloudflare/security-audit-skill)**  
> Security Audit Skill은 코딩 에이전트의 보안 조사에서 의심스러운 코드와 입증된 취약점을 구분하는 데 초점을 둔다. 아키텍처와 신뢰 경계, 입력 지점을 파악하고 조사 범위를 기록한 뒤, 후보를 발견한 에이전트와 별도의 검증자가 반증을 시도하도록 한다. 최종 기록의 소스 근거도 독립적으로 확인하며, 결과를 확정·추가 검증 필요·기각으로 구분한다.  
> 기계 판독 가능한 발견 기록과 조사 범위 장부를 남기므로, 후속 감사에서 누락 영역을 확인하거나 변경된 코드의 근거를 다시 검증하는 데 활용할 수 있다. 개발 관행을 스킬로 제공하는 mattpocock/skills와 비교하면, 보안 감사의 증거와 판정 절차를 구체화한 접근이다. 도구 사용과 병렬 하위 에이전트를 지원하는 모델, Node.js가 필요하며, 대상 코드를 실행하는 검증에는 운영체제가 강제하는 샌드박스가 요구된다. 이 격리 조건을 충족하지 못하면 대상 코드를 실행하지 않고 해당 후보를 추가 검증이 필요한 상태로 남긴다.
>  
> **[NVIDIA/auto-ontology](https://github.com/NVIDIA/auto-ontology)**  
> Auto Ontology는 기업 데이터의 용어와 지표 정의가 시스템마다 달라 에이전트가 질문을 잘못 해석하는 문제를 다룬다. 데이터베이스 메타데이터를 바탕으로 업무 용어, 열과의 연결, 테이블 관계, 재사용할 SQL 표현식을 구성한다. 사람이 이 정의를 검토하고 인증한 뒤 질의에 활용하는 구조로, 기존 의미 모델도 연결할 수 있다.  
> 자연어 질문을 관련 정의에 연결해 SQL을 만들고, 필터 값과 질의를 확인하며 답변에 SQL과 처리 근거를 함께 제공한다. MCP·CLI·API로 의미 정보를 노출하므로 여러 에이전트가 같은 업무 정의를 공유하는 데 활용할 수 있다. 세션의 작업 맥락을 유지하는 claude-mem과는 달리 데이터 자체의 공통 의미를 다룬다는 점에서, 에이전트에 필요한 맥락을 보완하는 또 다른 접근을 보여준다.  
> 생성한 온톨로지를 사람이 검토·인증해야 하며, 데이터가 뒷받침하지 못하는 질문에는 답변 불가를 알리는 구조다. 따라서 자동 생성만으로 지표의 정확성이 보장되는 것은 아니며 업무 정의를 관리할 담당자가 필요하다. 질의 기능을 운영하려면 연결할 데이터베이스와 추론·임베딩 등 모델 서비스도 함께 준비해야 한다.

```
생성 모델: gpt-6.1-sol
추론 수준: medium
```
