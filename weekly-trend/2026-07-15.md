# GitHub 주간 트렌드 리포트 (2026-07-15)

## 1. 개요

이번 주 트렌드는 AI 에이전트가 실제 업무 산출물을 다루는 방향으로 더 선명하게 이동했습니다. 구직, 오피스 문서, 코딩 에이전트 오케스트레이션, 영상 이해, 디자인 시스템, 장기 기억, 침투 테스트처럼 반복적이지만 결과 품질이 중요한 영역이 상위권을 차지했습니다.

에이전트 실행 환경과 보조 도구의 존재감도 큽니다. DesktopCommanderMCP, Orca, CubeSandbox, herdr, OmniRoute, codex-plugin-cc는 모델 자체보다 에이전트가 파일, 터미널, 워크트리, 샌드박스, 여러 AI 제공자를 안정적으로 다루게 하는 실행 계층에 초점을 둡니다.

디자인과 문서 자동화도 눈에 띄는 축입니다. OfficeCLI, archify, impeccable, astryx, hallmark는 AI가 단순 텍스트를 만드는 단계를 넘어 문서, 화면, 다이어그램, 디자인 언어까지 다루려는 수요를 보여줍니다.

## 3. 주요 리포지토리 분석

_[MadsLorentzen/ai-job-search](https://github.com/MadsLorentzen/ai-job-search)_

ai-job-search는 구직 과정을 하나의 구조화된 에이전트 워크플로로 묶습니다. 사용자의 경력 자료를 기반으로 프로필을 만들고, 채용 공고를 수집한 뒤, 적합도를 평가하고, CV와 커버레터를 직무에 맞게 작성하며, 면접 준비까지 이어지는 흐름을 제공합니다.

핵심은 구직자가 자신의 자료와 판단 기준을 로컬 저장소 안에 소유한 채 반복 업무를 자동화한다는 점입니다. 채용 공고 검색 기술은 특정 시장에 맞춰져 있지만, 자기소개 자료 구성, 직무 적합도 평가, 지원서 초안 작성과 검토라는 패턴은 다른 국가와 언어로 교체 가능한 구조입니다.

_[iOfficeAI/OfficeCLI](https://github.com/iOfficeAI/OfficeCLI)_

OfficeCLI는 AI 에이전트가 Word, Excel, PowerPoint 문서를 실제 작업 대상으로 다룰 수 있게 합니다. 단일 바이너리와 오피스 설치 없는 실행을 내세우며, 문서의 텍스트와 구조, 스타일, 수식, 차트, 이미지 같은 요소를 읽고 수정하고 새로 만들 수 있는 명령형 인터페이스를 제공합니다.

특히 렌더링 결과를 HTML이나 PNG로 확인해 에이전트가 만든 문서를 다시 보고 고치는 루프를 강조합니다. 이는 오피스 문서 자동화가 단순 파일 생성에서 끝나지 않고, 시각적 품질과 레이아웃 수정을 포함한 업무 자동화로 확장되고 있음을 보여줍니다.

_[stablyai/orca](https://github.com/stablyai/orca)_

Orca는 Codex, Claude Code, OpenCode 같은 CLI 기반 코딩 에이전트를 나란히 실행하고 관리하는 데 초점을 둔 개발 환경입니다. 각 에이전트를 독립된 git 워크트리에서 실행해 같은 요청에 대한 여러 결과를 비교하고, 선택한 결과를 병합하는 흐름을 지원합니다.

주요 기능은 병렬 워크트리, 모바일 동반 앱, 터미널 분할, 브라우저 기반 디자인 모드, GitHub와 Linear 작업 흐름, 원격 SSH 워크트리, diff 주석 기능입니다. 코딩 에이전트 사용이 단일 채팅 창에서 여러 실행 후보를 운영하고 검토하는 작업 관리 문제로 바뀌고 있음을 잘 보여주는 프로젝트입니다.
