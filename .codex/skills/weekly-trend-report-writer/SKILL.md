# 깃헙 주간 트렌드 리포트

## 작업 흐름
1. 원본 데이터 수집 규칙에 따라 깃헙 주간 트렌드 페이지(https://github.com/trending?since=weekly)를 직접 조회하고, 응답 본문을 `weekly-trend-draft/yyyy-mm-dd.source.html`에 변경 없이 저장.
2. 깃헙 주간 트렌드 페이지의 내용을 분석하고, 주요 분석 대상 선정 규칙에 따라 리포지토리를 선정.
3. 리포트 공통 작성 원칙, 섹션별 작성 규칙과 형식 제약 사항을 지켜서 리포트를 작성.
4. `weekly-trend-draft` 디렉토리가 없으면 생성하고, 리포팅 결과를 해당 디렉토리에 `yyyy-mm-dd.md` 파일로 저장. 파일명 내 `yyyy-mm-dd` 는 실행 환경의 `date +%Y-%m-%d` 명령 결과를 사용.
   - 리포트 제목 등 본문에 날짜를 표기할 때도 같은 명령 결과를 사용.
5. `node scripts/validate-weekly-report.js --report weekly-trend-draft/yyyy-mm-dd.md --source weekly-trend-draft/yyyy-mm-dd.source.html`을 실행해 리포트 형식, 수집 원본과의 정합성, 검증 시점의 최신 저장소 목록을 검증.
6. 검증에 실패하면 오류 원인에 따라 원본을 다시 수집하거나 리포트를 수정한 뒤, 검증을 다시 실행.
7. 검증이 통과하면 `.source.html`을 제외한 작업 중 생성한 임시 파일 삭제. `.source.html`은 실행기의 최종 검증을 위해 보존.

## 원본 데이터 수집
- 깃헙 주간 트렌드 페이지의 원본 URL을 직접 조회하고, 요청 시점에 원본 서버가 제공하는 응답을 분석의 기준으로 사용하세요.
- 내장 웹 검색, 검색 결과 스니펫, 검색 색인, 이전 실행에서 저장된 응답은 원본 데이터로 사용하지 마세요.
- 실행 환경에서 사용할 수 있는 직접 페이지 조회 또는 HTTP 요청 수단 중, 캐시된 사본을 재사용하지 않고 최신 응답을 요청할 수 있는 방법을 자율적으로 선택하세요.
- 선택한 수단이 캐시 제어 또는 재검증 기능을 제공한다면 이를 사용하세요.
- 리다이렉트나 중간 응답이 있으면 최종 응답이 요청한 깃헙 주간 트렌드 페이지인지 확인하세요.
- 직접 조회에 실패하거나 응답의 출처와 최신성을 합리적으로 확인할 수 없으면, 검색 결과나 추정값으로 대체하지 말고 작업을 실패 처리하세요.
- 응답 내용의 구조와 각 필드의 의미는 직접 분석하세요. 숫자의 위치만으로 의미를 추정하지 말고 주변 문맥, 레이블, 링크 대상을 함께 확인하세요.
- 주요 분석에 필요한 리포지토리 정보는 필요에 따라 README.md 페이지를 조회해 확인하세요.
  - README.md 에서 주목해야 하는 내용은 리포지토리 설명, 사용 또는 개발 목적, 주요 기능입니다. 실행 방법이나 예시, 설정 등은 분석하지 않습니다.

## 주요 분석 대상 선정
- 이번 주 트렌드 목록에 포함된 리포지토리 중 아래 기준을 만족하는 순서대로 최대 3개를 선정합니다. 이전 리포트의 선정 여부는 고려하지 않습니다.
  - 주간 ★가 많은 순서로 검토합니다. 동률이면 트렌드 페이지에 먼저 표시된 리포지토리를 우선합니다.
  - 주제는 리포지토리 설명과 핵심 기능에 나타난 주요 사용 목적을 기준으로 구분합니다. 예: 코드 작성·검토, 문서 처리, 영상 제작, 모델 추론.
  - 다른 주제의 후보가 있으면 동일 주제의 리포지토리는 최대 2개까지만 선정합니다.

## 리포트 공통 작성 원칙
- 아래 원칙은 개요, 리포지토리 목록, 주요 분석을 포함한 리포트 본문 전체에 적용합니다.
- 리포지토리와 트렌드에 관한 사실, 분석, 해석 근거를 담으세요. 분석과 해석은 리포지토리의 특징과 수치 등 확인한 사실에 근거해야 합니다.
- 수집 대상 안내, 자료 조회·도구 사용·데이터 정리·검증 절차, 분석 대상의 선정 과정과 선정 이유, 작성 규칙과 준수 여부 등 보고서 작성자의 작업을 설명하는 내용은 포함하지 마세요.
- 작성 후 모든 섹션에서 문장의 서술 대상이 리포지토리·트렌드인지 보고서 작성 행위인지 점검하고, 작성 행위를 설명하는 문장은 제거하세요.

## 섹션별 작성 규칙
- 개요
  - 이번 주 리포지토리에서 두드러지는 주제, 공통 흐름, 관심 분야와 그 의미를 구체적인 리포지토리나 기능을 근거로 설명하세요.
- 리포지토리
  - 깃헙 주간 트렌드 페이지에서 제공하는 리포지토리 목록을 모두 나열하세요. 임의로 누락하거나 추가하면 안됩니다.
  - 목록은 리포지토리 이름, 언어, 누적 ★, 주간 ★, 요약으로 구성합니다.
  - 요약은 한국어로 작성하세요.
- 주요 리포지토리 분석
  - 선정한 리포지토리의 목적, 해결하는 문제, 핵심 기능과 이번 주 트렌드에서의 의미를 자세히 설명하세요.
  - 분석 내용은 한국어로 작성하세요.

## 리포트 형식 제약 사항
- markdown 으로 작성합니다.
- assets/report-format.md 파일을 참고하여 리포트를 작성하세요.
- 다음 제한된 문법만 사용해야 합니다.
  - H1 (#), H2 (##)
  - bold (**text**), italic (*text* 또는 _text_)
  - hyperlink ([text](url))
  - 인용 (>), 코드 블록(```)
  - 줄바꿈(줄 끝 공백 2개)
